# 안전한 파일 보관과 공개 범위

## 기본 원칙

게시글을 비공개로 바꾸면 새 요청에서 글과 관리형 첨부파일을 제공하지 않습니다.
다운로드는 현재 공개된 게시글에 실제로 연결된 파일인지 먼저 확인합니다.
본문 이미지도 현재 공개된 글, 일정, 프로그램의 이미지인지 확인합니다.

이미 누군가 내려받은 파일이나 캡처까지 회수할 수는 없습니다.
외부 링크의 공개 범위는 해당 사이트에서 관리해야 합니다.
이 키트는 의료기록이나 상담기록을 보관하기 위한 시스템이 아닙니다.

## 처음 설정할 때

첨부파일 기능은 Vercel의 **Private Blob 저장소**를 사용합니다.
Vercel 안에 있는 기능이므로 다른 회사에 새로 가입할 필요는 없습니다.
Neon은 글과 설정을, Private Blob은 파일을 보관합니다.

1. Vercel에서 Blob 저장소를 만들 때 접근 범위를 Private으로 선택합니다.
2. 관리자 프로젝트에 연결합니다. 환경변수 접두사는 `PRIVATE_BLOB`으로 설정합니다.
3. 자동으로 만들어진 `PRIVATE_BLOB_READ_WRITE_TOKEN`은 관리자 프로젝트에서만 사용합니다.
4. `PRIVATE_BLOB_HOST`에는 해당 저장소의 정확한 호스트를 입력합니다.
   형식은 `YOUR_STORE.private.blob.vercel-storage.com`입니다. 비밀키가 아닌 주소입니다.
5. 관리자 앱을 다시 배포하고 로그인한 상태에서 파일과 이미지를 올려 확인합니다.

AI는 공식 CLI나 Vercel 화면을 이용해 도울 수 있습니다.
토큰을 채팅에 붙여 넣도록 요청하지 마세요. 공개 사이트에는 저장소 토큰을 넣지 마세요.
저장소가 준비되지 않았을 때는 업로드가 실패해야 합니다. 공개 저장소로 자동 전환하면 안 됩니다.

공식 안내: [Vercel Private Storage](https://vercel.com/docs/vercel-blob/private-storage)

## 기존 설치를 업데이트할 때

코드 업데이트만으로 과거에 공개 업로드한 파일이 잠기지는 않습니다.

1. 운영 DB와 기존 저장소의 대상 목록을 확인하고 저장소 밖에 백업합니다.
2. 기존 파일을 Private Blob에 복사하고 파일 크기와 SHA-256을 비교합니다.
3. 관리자와 공개 사이트를 새 버전으로 배포합니다.
4. 게시글의 파일 주소를 검증된 비공개 사본으로 바꿉니다. 원문과 작성일은 보존합니다.
5. 공개 글의 다운로드와 비공개 글의 접근 차단을 실제로 확인합니다.
6. 운영자의 승인을 받고 과거 공개 사본과 공개 콘텐츠 캐시를 제거합니다.
7. 예전 주소의 접근 차단을 확인합니다. CDN 전파가 끝나기 전에는 완료라고 말하지 마세요.

이전 기간에만 관리자 앱의 `BLOB_READ_WRITE_TOKEN`과 `LEGACY_PUBLIC_BLOB_HOST`로
정확히 지정된 기존 공개 저장소를 읽을 수 있습니다. 신규 업로드에는 사용하지 않습니다.
백업과 비교 증거가 없으면 원본을 삭제하지 마세요.
제3자 링크는 이 절차의 삭제 대상이 아닙니다.

## 공개 여부와 캐시

공개 읽기는 관리자 API를 통해 현재 DB의 공개 여부와 삭제 상태를 검사합니다.
공개 사이트에는 DB 비밀값을 전달하지 않습니다.
DB가 응답하지 않으면 오래된 글 사본 대신 오류나 빈 결과를 반환합니다.
샘플 콘텐츠는 API를 연결하지 않은 초기 상태에서만 사용합니다.

공개 목록에서는 일반 게시글의 긴 본문과 첨부파일을 DB에서 읽지 않습니다.
본문은 상세 요청에서만 읽습니다. 자료실 설명에 필요한 본문 조회는 자료실 게시글로 한정합니다.
공개 여부를 매번 검사하므로 캐시 전용 방식보다 DB 요청과 전송량이 늘 수 있습니다.
Neon 사용량을 확인하고, 비용을 줄이려고 비공개 전환 검사를 생략하지 마세요.

## 검증

- 두 앱에서 lint, typecheck, test, build와 `npm audit`을 실행합니다.
- 허용되지 않은 계정은 관리자 화면과 업로드에 접근할 수 없어야 합니다.
- 공개 글을 비공개로 바꾼 뒤 기존 파일 링크로 새 요청을 보내도 차단되어야 합니다.
- 본문 이미지도 같은 방식으로 확인합니다.
- 외부 저장소, 리다이렉트, 다른 글의 파일 주소를 넣어도 다운로드할 수 없어야 합니다.
- 토큰 없는 원본 Private Blob URL 요청은 차단되어야 합니다.
- 공개 GitHub에는 로컬 경로, 운영 DB 백업, 토큰, 비공개 자료를 올리지 않습니다.

테스트 통과는 모든 취약점이 없다는 보증이 아닙니다.
운영 Google 로그인, 실제 파일 업로드, 배포 상태는 각각 확인한 범위를 보고하세요.
